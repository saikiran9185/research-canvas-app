# Research Canvas — progress report

**7 September 2026** · [saikiran9185/research-canvas-app](https://github.com/saikiran9185/research-canvas-app) · AGPL-3.0-or-later

---

## Vision

An infinite canvas for research, so that artists working across fields can
gather the material a piece of thinking is actually made of — images, video,
audio, PDFs, documents — look at it properly, and think on top of it.

Not a drawing tool with files pinned to it. A place where **the source stays
attached to the note**.

## Mission

Three commitments, and every technical decision here follows from them.

**A board is a file you own.** Not a row in a database, not a document on
someone's server. A `.canvas` file of plain JSON in a real folder you can move,
rename, back up or sync. If this project disappeared tomorrow, your boards
would still open.

**Collaboration without a server.** Comments are append-only files, one per
author, that merge in a synced folder with nobody arbitrating. Two people can
work on the same board with no backend at all.

**Owned by the people who use it.** AGPL-3.0 so it cannot be closed, DCO rather
than a CLA so no one signs their work away, and a written path to community
governance.

## What makes it different

Every canvas tool can hold an image. This one keeps **the link back to where
something came from**: lift a passage out of a PDF and the card on the board
remembers the page it came from and takes you back to it. Pin a note to a frame
of video or a region of a page, and the note stays on that spot when the card
moves or resizes.

That is the product. The canvas is what it needs in order to exist.

## What was built today

34 commits. Grouped by what they were actually for.

### The rendering model was wrong

The whole board lived inside a div carrying `transform: scale(zoom)`. A CSS
scale rasterises its subtree once and stretches the bitmap — so every stroke,
arrow, letter, image and selection handle turned to mush on zoom. It read as an
image-resolution problem; it was the rendering model.

The camera now lives in an SVG `viewBox` for vectors and in screen-pixel layout
for everything else. Both re-render at device resolution at any zoom.

Alongside it, **level of detail**: at 8% zoom a 20pt label is a 1.6px smear,
so cards now degrade deliberately — full text, then the shape of the text, then
a plain block of their own colour.

### Selection became a real tool

It could hold one item and resize it only from the bottom-right, only by
growing. Now: rubber-band select, shift-click, eight handles, group transform
through one matrix, snapping to edges and centres, grouping, copy/paste,
option-drag to pull out a copy, z-order, nudge, zoom-to-fit, camera lock, and
item locking so you can draw over a reference without grabbing it.

### Stacking order can now be merged

Order used to *be* array position in the file, which two people cannot both
change. Every item now carries a fractional index, so reordering is a change to
one item's own field and two edits converge — the same way annotations already
did. This was the one correctness hole in the thing that makes the project
different.

### Text stopped fighting back

Text editing broke three times. The causes, in order: a captured pointer eating
the `dblclick`; a clock that mixed epoch milliseconds with page-relative ones;
and four independent global keyboard listeners each guessing whether the user
was typing by inspecting the event target.

The last one was the real fault. **An open editor now owns the keyboard**, and
every listener stands down — rather than four places each inferring it. Focus
is explicit rather than relying on `autoFocus`.

Text is also measured now rather than estimated. The old guess divided the box
width by `fontSize × 0.55` — the average advance of *Latin* lowercase — so it
ran short for Telugu, Devanagari and CJK alike.

### The library became a place

A permanent sidebar listed folders down the left edge while you were drawing —
250px of canvas answering a question you were not asking. There are two places
now: the library fills the window, and a board fills the window.

### Paste

Copy something in a browser and put it on the board. An image beats the URL
that came with it (a browser puts both on the clipboard, and the bitmap is what
you meant). A lone `http(s)` link becomes a card. A YouTube link becomes a
player with its timestamp preserved — as a poster until you press play, because
twenty clips should not be twenty iframes.

### Foundation

There was no linter and no error boundary. A render error unmounted the whole
tree and left a blank window with no message — which in a drawing app reads as
lost work. Both fixed. Refs written during render, which can hold a value from
a render that never committed, replaced with a safe helper.

`Canvas.tsx` went from 1,034 lines to 753, split into media cards, ink
rendering and the command set.

### Written down

- `docs/decisions/0001` — why this does not build on tldraw, Excalidraw or BlockSuite
- `docs/canvas-gaps.md` — what the canvas still needs, after reading a mature one end to end

## Where we are going wrong

Stated plainly, because a report that only lists wins is not a report.

**~~Nothing has shipped.~~** *Closed the same day.* v0.1.0 was tagged and the
pipeline — signing, CI, the updater — passed on its first run. v0.1.1 followed
because v0.1.0 was tagged mid-way through the text work and shipped without it;
a tag is a snapshot of a finished moment, not a milestone to reach for. The
installed app then **updated itself to v0.1.1**, which proves the last untested
half of the pipeline: releases now reach people without anyone downloading
anything.

What remains from this is not shipping but **notarisation**. macOS reports the
download as malware because Apple has not been paid to vouch for it.
`docs/INSTALL.md` explains that honestly rather than working around it quietly,
and it is the one thing standing between a stranger and a clean install.

**Bugs are still found by hand.** Most defects this week were found by using
the app and reporting them — the slow, expensive loop. The 165 tests are the
answer to that, and every one of them is a bug that actually shipped. The
interaction layer is now testable; the rendering layer is not.

**Three files still hold too much.** `Canvas.tsx` at 753 lines, `MediaViewer`
at 934, `App.tsx` at 843. AFFiNE has 70+ feature modules that each own their
state, logic and views. The counter-example is in this repo already: everything
moved into `geometry.ts` and `interaction.ts` has stayed fixed, because it
became testable the moment it had an edge.

**The interface is nearly consistent, which is worse than inconsistent.**
17 font sizes, 12 border radii, 43 hardcoded colours bypassing the tokens that
exist. Scales are now defined but not yet enforced.

## What is missing

**Frames and sections.** The largest remaining gap, and the one that matters
most for research: "these fourteen things are my typography references" is a
real unit of thought.

**Then, in order:** crop (so a screenshot becomes evidence rather than a
screenshot), rotation, real text measurement in export, markdown paste, a scene
object instead of array scans, and finishing the `Canvas.tsx` split.

## How the work is being done

Read mature codebases for their **grammar**, not their code. Excalidraw's own
note — that the array is a cache of order and the fractional indices are the
truth — changed the design of stacking order before a line was written. Their
tuned constants confirmed some choices and corrected others.

Interaction conventions and measured values are facts, not authorship: what
counts as a comfortable grab target is a fact about hands. We reference those
findings and choose our own values. No code has been copied from any of them.

Outside code is limited to single-purpose libraries — `perfect-freehand` for
ink, `fractional-indexing` for order. Nobody describes an application as "built
on top of perfect-freehand", and that is the test.
